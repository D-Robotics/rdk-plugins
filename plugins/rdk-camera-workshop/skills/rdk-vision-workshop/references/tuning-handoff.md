# 调优相机交给 BPU 检测

先确认当前boot、SDK/native、profile和独占者，保存选中tuning与原始可恢复版本。下列仅采用课前验证的一条路径：

A：由原采集服务继续独占设备，检测只消费受控输出；不得另启第二SDK消费者。复制帧后归还缓冲，分析/编码不阻塞持续采流。
B：停止本组调参预览并确认释放；配套检测runner新建匹配管线，受控加载选定配置，独立getter核对声明scope、实际自动输出，获得本轮新图，再进入推理。旧私有snapshot/layout不能跨SDK/profile照搬。

新demo可能载入原厂效果库。只有磁盘文件、旧工作区hash、模型框或进程存在时，不足以证明用了本次tuning。若缺少新检测管线getter/受控加载，标记tuning继承未验证，不能称端到端完成。

原生模块apply、完整厂商JSON、运行中热加载和初始化载入分别验。历史整库热加载曾增加颗粒，即使公开NR getter不变；不能为教学方便默认热切。独立服务的文件视图也可能与相机子进程不同，配置生效取实际getter和新图。

模型输入缩放与原相机图分开，保存letterbox逆变换。静态BPU通过后接当前帧，持续网页新图、框、检测消息、模型哈希与推理调用分别留证；模型benchmark FPS不能当整条视频FPS。

收尾按约定恢复原值或保留验收版本，核对配置、动态输出、流、新图与资源释放。只停止本任务拥有的进程，不宽泛杀相机/YOLO进程，不设未经请求的自启。
