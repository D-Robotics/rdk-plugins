# 四小时相机与 BPU 视觉 Workshop

先调用当前工具目录中的 `vision_course_plan`（宿主可附 MCP 前缀），读取实际随包课程版本、总时长、休息与阶段出口。阶段细节用 `vision_course_stage`。两工具只读且不探测设备；`planning_only/not_executed` 不能改写为真实执行通过。

部分Studio宿主导入后不会自动装配MCP或技能。工具缺失时按包内README从已安装副本生成显式MCP配置，保留其它服务；不得宣称目录可见即Agent可用。课程工具同时返回操作稿，不能自动匹配技能时仍可读取。

本插件提供课程编排和操作方法，不自带 GPU、SDK、相机服务或新的训练执行器。不要编造训练/部署 API。实际动作使用本次可见的宿主工具，沿用既有权限；工具缺失列出具体缺口，保留可做的软件准备，不借其它设备或用户身份。

## 首次检查与推进

1. 确认当前 Studio 形态、账号、实际连接板卡、相机插件/工具和独占状态。优先读取实际相机 runtime/capabilities/readiness；保存记录不表示当前在线。
2. 分别确认 GPU 项目、工具链主机和板端执行位置；Studio SSH 连上 X5 不等于有 GPU 训练环境。只读检查依赖/文件/当前任务，不通过启动训练来测试认证。
3. 读取[课程操作稿](references/course-runbook.md)。从当前阶段推进；已保存本组证据可复用，但新 boot/profile、场景变化与未确认恢复必须重新核对。用实际证据判断，不由操作员或模型填写虚假 pass。
4. 用户要求执行时，在当前授权范围完成实际可用步骤。读取日志/轮询已有 run，不重复提交异步训练或写入。触及现场物理调整时说明具体所需动作，不猜镜头、排线或寄存器。
5. 最后分别报告安装/技能匹配/工具装配/真实 Agent 调用/训练/量化/BPU/画质/整课的完成范围。

## 阶段与条件

- 0–40 分钟：开场、连接、实验与已有驱动点亮；失败切备用设备。
- 40–80：固定场景、完整原始快照、有界 ISP A/B/A、选版与恢复。
- 80–100：少量现场采样/标注体验，合入课前审查数据，按采集批次划分。
- 100–135：预训练轻量检测模型短程 GPU 微调，含110–120休息。
- 135–165：固定导出、校准、目标 X5 编译与同图核对。
- 165–190：模型、labels、前后处理成套上板，静态图真实 BPU 验证。
- 190–230：调优相机接 BPU 实时示例、固定条件对比。
- 230–240：成果、恢复与释放。所有备用模型明确来源。

## 关键约束

相机独占。写前保存原始完整声明 scope；应用→独立 getter→新图→A/B/A；参数生效与画质改善分开。未确认写入先查账本/实际状态，不盲目重放。错误/取消后确认配置、自动输出、流和终态新图。

GPU训练、ONNX导出、PTQ编译、BPU推理分别留证；BPU不负责本课训练。训练 loss、导出文件存在、进程存在、页面打开分别不足以完成下游验收。模型/数据/类别/输入输出/预处理/解码全链绑定，不使用不相关COCO模型冒充本组自定义模型。

检测进程重新开流可能重置ISP。读[检测交接](references/tuning-handoff.md)后选择已验证的共享流或受控重开方案，核对检测管线 getter 和当前图；不能由旧调参图推断新检测流仍用同一 tuning。
