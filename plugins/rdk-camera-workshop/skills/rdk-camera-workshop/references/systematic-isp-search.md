# 系统性 ISP 调试：由新图到可复验的组合配置

用于“曝光、降噪、锐化都调一遍”“别只改白平衡就算完成”“做到当前现场最佳”。这是已实机执行的方法；参数范围与结论必须重新绑定本次 Sensor、模式、SDK、库及现场，不能把 IMX415 的数值套给新型号。

1. **先列完整验收范围。** 分开记录曝光、空间降噪、时域降噪、锐化、色彩和必要的对比度。参数生效、当前画质选优、全场景标定、插件上线是不同结论。只完成白平衡不能关闭更广的系统调试目标。
2. **新采基线并核对控制权。** 检查当前连接、boot、库哈希、独占owner和恢复能力；先通过有界连续帧窗口再写ISP。保存当前原始属性、实际描述符和同场景3张新图，不把旧照片当新基线。
3. **先单项，后组合。** 空间/时域降噪、锐化对照时，固定实际当前AE和选定WB；曝光对照保持AE AUTO，若版本支持则比较其固定目标亮度，记录收敛过程、SDK曝光/增益及高光/暗部变化。API目标亮度不等于物理曝光；没有测量不认证时钟或秒值。自动算法尚未收敛时继续观察新帧。
4. **只用实际类型构造候选。** 从每个模块自己的descriptor读取mode/字段offset、type、count和大小；AE mode的位置不能套给EE/NR。需要完整数组时，用当前安装头文件编译纯layout探针并绑定源码、可执行文件、头文件哈希，探针不调用SDK。保留其他字节，包括未声明字段。官方范围与本次较窄的相对变化包络分别记录。
5. **双向粗调、局部细调。** 先降低/提高一个维度，各候选实际写入、严格回读、至少6次跨时间采样和3张新图，随后恢复基线再拍A2；再在有希望的区域取中间值。NR自动表须确认有效档数、gain网格及各分量，不能把首槽当所有ISO。达到上限而请求被截成原值是no-op，不算更强候选通过。
6. **图像评价不能被统计替代。** 对照原图、当前最好与新候选；噪点、字边光晕、笔画损失、颜色、曝光逐项比较。processed PNG逐帧差、梯度、直方图只作诊断，不当SNR/MTF。更亮、更平滑或边缘更强都不自动算更好。记录取舍；无收益的模块可保留原值，但必须有实际测试证据。
7. **持续采流，分离分析。** 复用[单消费者助手](../scripts/continuous_frame_pump.py)：metadata callback只取帧/释放并返回实际元数据，picture callback复制新帧且释放SDK缓冲后返回`(bytes, metadata)`；主线程编码、存盘、匹配图像时，后台继续取帧。所有SDK控制和帧调用须由已验证的ctx互斥串行化。禁止另一个预览消费者绕开pump；每次重新开流新建pump。
8. **先停消费者再关设备。** `stop()`必须join成功后才能pause/close SDK；保留原生失败码，不能在线程仍使用ctx时关闭native。pump计数只说明消费了帧，不替代连续帧/速率资格检查。已观察到它改善编码/落盘间隙，不证明所有取帧故障都由CPU造成。
9. **把临时状态也当待恢复。** 每次setter前写持久intent；即使严格回读失败，也可能已部分应用。异常时尝试恢复所有已改模块，单模块严格回读，全部恢复后再做完整scope比较，不能因第一个恢复错误放弃其余模块或提前把混合状态当恢复成功。保留首个错误和全部恢复错误。
10. **组合重新验证并重复加载。** 选定各项后做组合A/B/A，观察模块耦合，导出实际属性；从新进程再次加载同一份已保存配置，回读并拍新图，独立原管线复验。恢复原值成功不等于候选画质通过；配置存档不等于它已常驻或自动开机启用。
11. **按真实范围交付。** 输出参数表、每轮选择/拒绝原因、实际新图/恢复图、SDK属性与哈希、失败回执、重载证据和剩余问题。CORE4快照不包括额外NR时，额外属性单独存档、明确scope，不能拼成“全模块厂商tuning已验证”。最佳结论限定实际场景及试验范围，不因目标难以达到就把目标缩成最容易通过的一项。

助手只提供并发采流/错误传播逻辑，没有主机、凭据、Sensor驱动或任意寄存器写入。它是待宿主接入的源码，不会注册MCP工具，不得借此宣称新型号或生产Agent能力available。测试：`python3 skills/rdk-camera-workshop/scripts/continuous_frame_pump.test.py`（源码仓库中加插件目录前缀）；发行包按现有规则不含测试文件。

实机依据：2026-10-16 IMX415 在同一boot下执行AE target36/42/48/54/60、2DNR有效档全3分量0.5/1/1.125/1.25/1.5、3DNR96/128、EE32/48/80，以及对比度1/1.05/1.10的对照。3DNR128已达官方上限，上调被截为原字节，明确不作为增量。一次mode布局误用和一次写入前连续帧失败均保留；后续独立重试通过。具体最佳数值必须查对应实际交付记录，不能从本页直接写设备。

字段语义与公开范围以[官方ISP API](https://developer.d-robotics.cc/x5_sdk_doc_v2.0.0/multimedia_development/5-ISP_Tune_API_zh_CN.html)及当前安装头文件为准：例如AUTO exposure target、2DNR sigma_scale、3DNR strength。官方表未提供的上下界不能编成SDK认证范围；本次有限相对包络仍标为私有操作策略。

## 暗光场景与曝光响应排障

现场从文字卡变成近乎全黑时，先保存新图与实际 SDK 属性；旧文字卡 guard 拒绝时应在零 ISP setter 下退出。用户将暗光纳入目标后，建立独立夜间场景记录，保留白天配置；不能沿用白天纸卡的手动 WB。原场景的完成状态也不能关闭新增场景目标。

- 同时读曝光时间、模拟/数字/ISP 增益和当前 SDK 范围，区分时间上限与增益上限。Getter 范围只说明 SDK 声明范围，不认证物理曝光/增益，也不保证自动算法会用满它。
- AUTO 目标值回读改变后，继续观察实际曝光/增益和新帧。2026-10-17 IMX415 暗光实测 target48→60/72 均严格回读通过，15秒各6次采样的曝光30ms、again约5.907、ISP gain约1.996未变，新图无可靠改善；记录为“属性改变但未观察到有效曝光响应”，根因仍待查。
- 核对实际曝光分解表，而不只看通用 gain 范围。该现场原表6个有效节点，后5个节点均为30ms、again约5.948、ISP gain约1.995。将后续档位扩至1.5/2倍后，表本身严格回读通过，AUTO输出仍未变化；随后以当前值进入MANUAL再重新提交原AUTO属性，1.5倍表实际观察到again约8.915。这个组合仅在本次SDK/模式验证，不能推断所有版本都需要同一重载顺序。
- **恢复表值不代表自动算法输出已恢复。** 上述试验恢复原表后，AUTO gain仍保持8.915；最终再次提交原曝光AUTO属性后才回到5.907，AE统计帧号持续更新。恢复流程须保留原表及曝光属性，重新触发后观察实际输出和新图；自动输出被排除在normalized比较之外，不能用该比较独自证明曝光行为回归。无需根据配置字段名称猜改全局JSON；运行时重载先实际验证。
- WDR从MANUAL切回AUTO后，本现场getter的当前strength仍保留128，原始AUTO当前strength为0。2026-10-17独立试验先在MANUAL下写回原始数值，再提交原AUTO属性，六次实际getter均观察到mode0、strength0，并采到恢复图、完成独立原管线复开。保留两次setter及其失败intent；不能只写AUTO模式就声称当前数值已恢复。该顺序只绑定已验证的SDK/属性，不推导所有自动模块都应强制手动写值。
- 需要区分自动控制问题与画面响应时，可先对实际当前曝光做数值不变的 MANUAL 过渡并严格回读，再在当前 SDK 范围与较窄私有包络内试一个增益字段；保留其他增益和时间，不猜 Sensor 寄存器。该现场 again2倍/4倍出现更多轮廓，也明显放大颗粒和横向色带，不能把更亮当成整体最佳。
- 降噪/锐化对照固定同一曝光与当前 WB；若用 AUTO 表，覆盖所有有效 gain 档并记录网格，不能把首档锐化改动当成高 ISO 锐化测试。固定色带与随机颗粒分别观察；尚未排除的读出、频闪或标定因素不要写成已确定根因。
- **WDR须看多帧，不按首帧定优劣。** 当前暗光的strength128、lowStrength144/176都提升了天花板/线缆可见度，也放大了噪声；各3张新图的亮度/颗粒波动范围重叠，首帧的优劣关系在后续帧中反转。稳定的SDK回读不等于稳定画面。可增加第二组三张新图并保持同一控制scope，另行核对阻尼与时间波动；不要把一次144与176的比较写成稳定最优。无明显文字目标时也不能给出文字清晰度验收。
- 噪声较大的4K PNG可能显著增大，按实际编码/落盘和原生关闭耗时安排 owned-process 正常期限，同时保留独立 TERM/KILL 恢复时间。父进程超时时仍汇总最终子回执的真实 setter 数，记录哪一步超时、参数恢复与原管线复开是否分别通过；不能用父级初始写入数0覆盖实际已执行写入。
- 最终验证若会向journal追加字段，应在追加完成后再封存receipt的journal SHA。一次私有验证器在已有SHA之后追加两个验证字段，已保留原回执并通过去掉这两个字段重现旧SHA、另记最终SHA来说明过渡；不能静默改写历史回执或只凭协议状态掩盖摘要不一致。

上述是现场已观察到的分支与排障方法，不代表暗光画质已验收、自动曝光根因已解决或新原子工具已发布。

## 归档多帧的行色差诊断助手

画面出现水平彩条、局部闪动或“均值稳定但观感不稳定”时，可运行[只读行色差脚本](../scripts/temporal_row_diagnostics.py)。需要Python、NumPy和Pillow；缺少依赖时先配置当前工作环境，不把脚本可用等同于宿主已经提供MCP原子工具。脚本不连接设备、不改ISP、不进行候选排名。

输入清单的例子：

```json
{
  "schema": "camera-temporal-row-diagnostics-v1",
  "journal": {"file": "response.json", "sha256": "实际归档journal的64位SHA256", "phase": "candidate-1"},
  "roi": {"x": 1800, "y": 0, "width": 1700, "height": 1200},
  "detrendWindowRows": 129
}
```

ROI按本次实际图像选择，不照搬例子。归档journal使用`phases[].label/images/additionalImages`，每张图含`name/sha256/frame`；frame内包含实际记录的`width/height/frame_id/timestamp_ns`。同一组3–8张8位RGB PNG，脚本核对文件哈希、尺寸、单调帧号与时间、根目录边界；两组三张可以合并为六张。时间和控制状态的真实性仍需采集器回执单独验证。输出采用新文件，不覆盖已有归档。

```bash
python3 skills/rdk-camera-workshop/scripts/temporal_row_diagnostics.py manifest.json --root /path/to/archive --output observation.json
```

源码仓库执行时在脚本路径前加插件目录。输出保留每帧ROI码值、去趋势后行色差RMS、行周期谱峰、相邻帧行轮廓相关性及记录的采样间隔。它们都是processed RGB观察量，不能称为RAW噪声、SNR、真实频闪频率或坏传感器诊断；场景纹理、运动、光照与ISP仍可能混杂。

2026-10-17实际六帧阻尼归档中，原127的ROI均值跨度约0.099码值，32约0.244、64约0.148；32和64都出现过高于原127六帧范围的行色差突增。它解释了为何只按全图均值或首帧选优不充分，仍不能据此判定光源或Sensor根因。源码测试含恒定纹理、相位变化、均匀亮度变化、零方差、两组三帧、哈希篡改、重复帧、尺寸/ROI错误、越界符号链接和拒绝覆盖输入；用`temporal_row_diagnostics.test.py`执行。Studio打包器已为此助手与单消费者助手增加明确脚本清单，测试文件仍排除；该源码/fixture验收不代表插件已发布或MCP已注册新操作。

## RAW 行变化与 ISP 彩条分层定位

PNG 彩条不能直接归因于锐化、WDR 或光源。先在匹配 SDK 的只读 RAW 诊断库上验证当前 NV12 连续取帧、显式关闭和独立原管线复开；旧启动或不同库的 RAW 回执不能替代当前资格。诊断辅助文件也应纳入安装清单和哈希前置检查，缺失时在创建相机 context 前退出。

RAW 与 ISP/NV12 分别维护帧序。只允许一个消费者访问同一流，持有的帧须实际释放；RAW 调用前记录 intent，即使失败也计入调用数。CPU 编码/文件落盘期间持续排空 ISP 流，停止并 join 消费线程后才关闭。记录 RAW 与前后 NV12 的帧号/时间关系；仅元数据相同不等于已保存同帧 PNG，更不认证物理曝光。未知 Bayer 时保留四个未标注颜色的2×2像素相位，不猜 RGB，不启动 RAW 回灌或黑电平标定。

已保存3–8张 unpacked16le RAW10 时，可运行[只读 RAW 行相关脚本](../scripts/raw_row_coherence.py)：

```json
{
  "schema": "camera-raw-row-coherence-v1",
  "receipt": {"file": "receipt.json", "sha256": "实际归档回执的64位SHA256"},
  "roi": {"x": 1800, "y": 0, "width": 1700, "height": 1200},
  "detrendWindowPhaseRows": 65
}
```

回执包含`rawCalls/rawTransportVerified/rawBytesPersisted/rawFrames`；每帧含`name/sha256/nativeCode/frame`，frame使用采集器实际记录的尺寸、stride、size、10bit、packing0、unknown Bayer `4294967295`、alignment0或1、帧号和SDK时间。脚本核对字节长度、哈希、右/左对齐的唯一性、单调帧序和根目录边界；ROI必须按实际场景选择、坐标和尺寸为偶数。窗口按相位行计数，65相位行对应约130传感器行。

```bash
python3 skills/rdk-camera-workshop/scripts/raw_row_coherence.py manifest.json --root /path/to/archive --output raw-observation.json
```

相邻归档帧相减后，分别计算每个未标色相位的行均值变化，并把该相位内交错列分成两组比较。高相关说明变化包含两组列共同的行分量，不能单凭它判断坏Sensor、供电、时钟或灯光频闪；场景运动与光照仍可能混杂。时间间隔来自稀疏归档帧，不能推算真实频闪频率。

2026-10-17当前暗光实测3张4K RAW：四相位的两次相邻差分中，两组交错列行变化相关性约0.966–0.976；部分不同相位的行变化反相关。行变化在进入ISP前的数据中已能观察到，因此不能只靠锐化判为解决。仍需受控光照/用户确认遮光的对照，不能将未确认的黑图标记为遮光图。本次RAW是在原始ISP属性下采集，不能直接当作之前增强增益/WDR候选的同帧根因证明。

此助手只处理归档、需要NumPy，输出始终保留画质、根因、Bayer、元数据真实性及同帧ISP配对未认证。已通过8项软件测试，并在本次3张实机RAW上复现独立分析的8组相关性；Studio打包白名单已包含源码。这不代表已发布、注册新MCP操作或ISP已调到最佳。

WDR降低强度也必须同场景验证，不能假定更弱就更干净。2026-10-17后续固定曝光表/NR/EE/AWB对照strength128/64/96，每档6张新图；64/96的暗区明显更暗，彩条未消失，部分行色差残差高于128样本，未替换原提亮候选。实际SDK数值变化、暗部可见度和行噪观察应分别记录，不能用更低亮度或更小PNG大小替代画质改善。该轮原WDR数值→AUTO、AE表→AUTO重提交及独立原管线恢复均通过，journal验证未在SHA封存后追加字段；物理根因和最佳画质仍未验收。

## 3DNR 强度到上限后的分支

先区分强度、参考帧历史长度、运动历史长度、运动分类和噪声标定模型。[官方3DNR说明](https://developer.d-robotics.cc/x5_sdk_doc_v2.0.0/en/multimedia_development/isp_tuning_guide/isp_tuning/isp_tuning.html)给出参考IIR窗口`filterLen`及运动IIR窗口`filterLen2`，两者不是同一个量；强度128只代表对应输出混合强度达到该字段上限，不意味着所有降噪参数都已调到最佳。API文档范围与实际安装头文件/字段布局须分别核对。

2026-10-17实测前先在当前板卡头文件上纯编译`sizeof/offsetof`，没有创建相机context或执行setter。对当前2448字节3DNR结构，仅修改AUTO表中有效ISO档位的参考`filter_len`字节，保留运动历史`filter_len2`、强度、噪声模型、增益网格与无效尾档。范围1–99不等于应取99；本现场仅对照16/32/48。私有候选字节构造测试核对实际差异位置，不用猜测结构偏移。

当前SDK getter六次均观察到参考长度16→32→16→48→16，运动历史长度保持16；曝光、WDR及其它配置scope独立核对。长度48组的行色差出现下降迹象，但串行六帧不能证明稳定最佳，须独立重开后复验并观察返回原值的多帧。即使静态条纹降低，仍须另验运动拖影与细节，不能把延长历史窗口的静态结果直接作为通用preset或物理根因修复；不要拿未标定的暗场统计改写NoiseProfile。

## 用文字任务复核降噪取舍，保留OCR证据边界

调降噪时，先从本轮新原图选定文字及平坦区域，后续原值/候选/恢复全部复用ROI；保留每张原图SHA、裁剪SHA和坐标。不要以Laplacian增大、全图均值下降或二维码一次成功单独授予清晰度通过。曝光、白平衡与目标几何变化分别核对，先让已支持模块的当前输出跟随请求，再评价画质。

macOS宿主可选编译[只读OCR源码](../scripts/text_ocr_observation.swift)，需要本机Swift、Vision、ImageIO、CryptoKit；不是板端Linux依赖，缺少环境不冒充已执行。以技能目录为工作目录，编译产物留在单独本机目录，不打入源码插件：

```sh
mkdir -p .local-observers
xcrun swiftc scripts/text_ocr_observation.swift -o .local-observers/text-ocr
.local-observers/text-ocr archive/ocr-manifest.json --root archive --output archive/ocr-result.json
```

manifest的schema为`camera-text-ocr-observation-v1`，`frames`为1–64项`{file,sha256}`，file是归档根内相对路径，例如`crops/original-main-1.png`；sha256必须是该实际裁剪PNG的哈希。只接受8位RGB PNG、单文件不超过32MiB、图像不超过1600万像素。拒绝越界/符号链接逃逸、同一路径的重复别名、哈希不符、过大输入及覆盖已有结果。它只核对裁剪字节，不认证来源SDK或原图身份；原图到裁剪的绑定清单必须另存。

实际使用Vision accurate、zh-Hans/en-US、关闭language correction、不传customWords，保留每帧全部识别行、引擎confidence、位置和revision；识别失败/空结果也保留，不筛掉。参考转录仅用于输出后的文字任务核对，不把答案塞给识别器。关闭纠错仍不消除识别模型先验；confidence不是校准正确率，文字完全识别也不能证明MTF、细笔画分辨率或其它新字体都好。它是只读本地观察器，不是新的相机控制或AI自主Run。
